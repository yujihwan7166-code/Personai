# 메모+보드 / 위키 재설계 계획서

> 작성 2026-07-06. 이 문서는 "메모·보드·위키"를 재설계하기 위한 합의 사항·주의점·단계별 로드맵을 담는다.
> 코드가 아니라 **결정과 순서**를 기록하는 문서다.

---

## 0. 큰 그림 (한 줄)

> **제품은 둘. "생각하는 곳"(메모+보드)과 "정리된 지식"(위키).**
> 어려운 부품은 **잘 만든 오픈소스를 가져다 쓰고**, 그 위에 **우리 사이트 옷(디자인 토큰)** 을 입혀 우리 앱처럼 만든다.

- 기존 메모·위키는 **버리고**, 검증된 오픈소스를 참고/차용해 **더 좋게** 다시 만든다.
- 워너비: **옵시디언**(개인 지식 그래프) + **AFFiNE 식 문서↔보드 결합**.

---

## 1. 전제 조건 (반드시 지킴)

- **조건 1 — 재사용 우선**: 우리가 전부 만들기보다, 더 좋은 오픈소스가 있으면 참고하거나 붙여서 쓴다. (바퀴 재발명 금지)
- **조건 2 — 디자인 일치**: 메인·플래너와 **색·폰트·여백·둥근모서리·그림자(디자인 토큰)** 가 일치해야 한다. "같은 사이트, 다른 방."

> ⚠️ 그래서 **앱을 통째로 이식하지 않는다**(AFFiNE·Outline 등). 통짜는 자기 생김새가 강해 우리 톤과 겉돈다.
> **부품(라이브러리)·로직·패턴만** 가져와 **우리 디자인 토큰으로 재도색**한다.

---

## 2. 핵심 요구사항

1. **메모+보드는 한 문서.** 문서 하나에서 **[글 | 판] 토글**로 메모↔보드 전환이 가능하고, **한 문서에 글(메모) 정보와 판(보드) 정보가 둘 다 저장**된다.
2. **메모 → 위키 승격**이 가능하다. 승격 시 **글(메모)만** 위키로 넘어가고 **판(보드)은 승격되지 않는다**(원래 노트에 잔류).
3. **메모와 위키의 편집기·내부 포맷은 동일**하다. → 승격은 "변환"이 아니라 **"메타데이터 부여"**.
4. **위키는 링크 중심**: `[[위키링크]]` 자동완성 · 백링크 · 트랜스클루전 · **전역 그래프**.
5. **메모(=위키) 편집기는 노션 수준**의 블록 에디터.

---

## 3. 데이터 모델 (개념)

**노트(Note) 하나가 글과 판을 모두 품는다.**

```
Note {
  id, title,
  글(memo)  : 블록 문서 (노션급 에디터)
  판(board) : 무한 캔버스 (tldraw)
  meta      : surface('memo'|'wiki'), type, status, tags, links[]
}
```

- **메모** = surface:'memo' (메타 최소)
- **위키** = surface:'wiki' + 유형·관계 채움 + 그래프 편입
- **승격** = 글 부분을 위키 문서로 (내용 그대로 + 메타 부여). 판은 원 노트에 남고, 원본↔위키는 상호 링크.

---

## 4. 채택 스택 (adopt) — 전부 무료

| 역할 | 채택(1픽) | 대안 | 라이선스 |
|---|---|---|---|
| 블록 에디터 (메모·위키 **공유**) | **Plate** (shadcn/Tailwind, 디자인 일치 최상) | BlockNote(빠름), Novel(+AI) | MIT ✅ |
| 보드(캔버스) | **tldraw** | Excalidraw(MIT) | tldraw 워터마크/상용 라이선스 **확인 필요** ⚠️ |
| 그래프 렌더 | **Sigma.js** (WebGL, 수천 노드) | react-force-graph | MIT ✅ |
| 검색 | **Orama** | MiniSearch | MIT ✅ |
| 저장/로컬퍼스트 | **Yjs + IndexedDB** (오프라인·히스토리·미래 협업) | 단순 JSON 스토어 | MIT ✅ |

> **편집기는 반드시 하나**를 골라 메모·위키가 함께 쓴다(요구 3의 전제).

## 5. 위키 참고 오픈소스 (내용·로직만 차용, UI는 재도색)

| 가져올 것 | repo | 라이선스 | 비고 |
|---|---|---|---|
| 위키링크·백링크·그래프 **렌더/표현** | **Quartz** (jackyzha0/quartz) | MIT ✅ | 코드 차용 OK |
| 링크 인덱싱·백링크·unlinked mention **로직** | **Foam** (foambubble/foam) | MIT ✅ | 코드 차용 OK |
| **AI 자동 연결** 기능·UX 아이디어 | **Reor** (reorproject/reor) | AGPL 🟡 | **패턴만** 참고, 코드 복붙 금지 |
| UX 골드 스탠다드 (흉내) | Obsidian | 비공개 | 목표점 |

> 팀 위키(Confluence/Notion식) 방향이 아니라 **개인 지식 그래프(옵시디언식)** 로 확정.

---

## 6. 우리가 직접 만드는 것 (오픈소스에 없는 "제품의 뇌")

- 메모↔보드를 **한 문서에 담고 토글**하는 방식
- **위키 승격** 규칙 (글만, 메타 부여, 상호 링크)
- **`[[링크]]` 자동완성 · 백링크 · 트랜스클루전** (위키의 진짜 심장)
- **디자인 토큰 입히기** (모든 채택 라이브러리에 — 조건 2)
- 유형 택소노미: **개념 · 인물 · 결정 · 리서치 · 도구 · 색인(MOC)** (유형은 배지 색으로만)

---

## 7. 위키 화면·문서 구성

**화면(3기둥 + 전역 그래프):**
- 왼쪽: 유형별 트리 + 검색
- 가운데: 한 컬럼 문서(주인공)
- 오른쪽: 목차·백링크·관련문서·작은 그래프(조용히)
- 상단: 전역 그래프 열기

**문서 한 장:** 유형 배지 → 제목(세리프 한 방울) → 가벼운 메타 → 본문(링크 연결) → 연결정보 4종(연결한 곳·백링크·관련·로컬그래프).

**디자인 톤:** "조용한 문서 중심". 색은 배지에만, 나머진 여백·헤어라인·타이포. 좌측 공용 레일 유지 → 이동해도 골격 불변.

---

## 8. ⚠️ 주의점 (반드시 기억)

1. **앱 통짜 이식 금지** — AFFiNE/Outline 등. 라이브러리·패턴만, UI는 우리 토큰으로 재도색. (조건 2)
2. **라이선스 규율**
   - MIT (Plate·BlockNote·tldraw*·Quartz·Foam·Sigma·Orama·Yjs): 사용/차용 OK.
   - AGPL (Reor·Logseq·SiYuan): **아이디어·UX만 참고, 코드 복붙 금지.**
   - **tldraw**: 워터마크 제거/상용은 별도 라이선스 — **도입 전 반드시 확인.**
3. **편집기는 메모·위키 공용 1개** — 안 그러면 승격이 "변환"이 돼 무너진다.
4. **기존 데이터 처리 방침 결정** — 지금 메모·위키에 실제 내용이 있으면 마이그레이션할지, 폐기할지 **먼저 정한다.**
5. **그래프는 "보상"이지 "엔진"이 아니다** — 헤어볼부터 만들지 말 것. **수집→링크→정제 마찰 제거**가 먼저, 그래프는 그 결과.
6. **큰 그래프는 WebGL(Sigma)** — Cytoscape는 수천 노드에서 버벅인다.
7. **위키의 진짜 가치 = `[[ 자동완성 · 백링크 · 트랜스클루전`** — 여기에 힘을 쓴다. 편집기 화려함이 아님.
8. **보이지 않는 90% = UX 다듬기 + 통합 + 디자인 재도색** — 일정에 반드시 반영.
9. **스코프 관리** — 진짜 "블록 단위 문서↔캔버스 듀얼"(AFFiNE 급)은 안 만든다. 우리는 **"한 문서에 글/판 두 면, 토글"** 까지. 듀얼은 필요해지면 나중에 BlockSuite로 별도 검토.

## 9. 단계별 로드맵 (순차)

각 단계는 되도록 "그 자체로 돌아가는" 상태로 끝낸다.

### 0단계 — 준비·결정
- 최종 스택 확정: **에디터(Plate 유력) / 캔버스(tldraw) / 그래프(Sigma) / 검색(Orama) / 저장(Yjs)**
- **라이선스 점검** (tldraw 상용 조건, AGPL 제외)
- **기존 메모·위키 데이터** 마이그레이션 vs 폐기 결정
- **디자인 토큰 매핑 규칙** 정의 (각 라이브러리에 우리 토큰 주입 방법)

### 1단계 — 공용 노트 substrate + 노션급 에디터
- 노트 데이터 모델 `{ id, title, 글, 판, meta }` + 저장/로드(로컬퍼스트)
- **Plate 도입 + 우리 디자인 토큰 입히기** (글 모드)

### 2단계 — 메모+보드 결합 (요구 1)
- 노트 화면에 **[글 | 판] 토글**
- 판 모드 = **tldraw**, 같은 노트에 저장
- "한 문서에 둘 다 저장·전환" 검증

### 3단계 — 위키 뼈대 + 편집기 공유 (요구 3)
- 위키 = **같은 에디터**, 3기둥 레이아웃
- 유형·상태·태그 메타 + 유형 배지
- 좌측 공용 레일에 위키 편입

### 4단계 — 링크·백링크·트랜스클루전 (Foam 참고)
- `[[ ]]` 자동완성, 백링크 인덱스/패널, `![[ ]]` 임베드, unlinked mention

### 5단계 — 승격 (요구 2)
- 메모의 글 → 위키 문서 생성/이동 + 메타 부여
- 판은 원 노트에 잔류, 원본↔위키 상호 링크

### 6단계 — 그래프 (Quartz/Sigma 참고)
- 로컬 그래프 + **전역 그래프(Sigma WebGL)**
- Quartz의 렌더·백링크 표현 차용 + 우리 토큰

### 7단계 — 검색·마무리 (Orama)
- 전문/퍼지 검색, 유형 트리, 전체 다듬기

### 8단계 (보너스) — AI 거들기 (Reor 아이디어)
- 링크·엔티티 **자동 제안**으로 그래프가 손노동 없이 촘촘해지게

## 10. 한눈 요약

| | 메모+보드 | 위키 |
|---|---|---|
| 담는 것 | 글+판 한 문서 | 정리된 지식 |
| 편집기 | **공용** 노션급(Plate) + tldraw 캔버스 | **공용** 노션급(Plate) |
| 승격 | 글만 위키로 | (승격의 도착지) |
| 무드 | 자유로운 작업대 | 차분한 서고 |
| 디자인 | **같은 토큰** | **같은 토큰** |

**요약:** 어려운 부품은 오픈소스, **두뇌(결합·승격·링크·그래프)와 옷(디자인)은 우리가.** 이러면 조건 2개·요구 5개가 전부 충족되고 워너비에 **가장 싸고 안전하게** 도달한다.
