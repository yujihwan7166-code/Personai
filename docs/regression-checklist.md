# Regression Checklist

Personai는 여러 도구가 같은 상태와 라우팅을 공유하므로 작은 수정도 다른 모드에 영향을 줄 수 있습니다. 기능을 수정하거나 배포하기 전에 아래 순서로 확인합니다.

## 자동 검증

```bash
npm run typecheck
npm test
npm run build
npm run smoke:core
```

로컬 서버가 이미 떠 있으면 다음처럼 실행합니다.

```bash
SMOKE_BASE_URL=http://127.0.0.1:3001 npm run smoke:core
```

## 핵심 화면

- `/`: 일반 채팅 화면이 열리고 모델 목록과 입력창이 보인다.
- `/`: 온보딩이 첫 렌더를 즉시 막지 않고, 표시 후 건너뛰기로 닫힌다.
- `/`: 일반, 토론, 공부 모드 전환이 동작한다.
- `/planner`: 오늘 타임라인과 주간 스트립이 렌더링된다.
- `/wiki`: 스타터 팩 또는 빈 페이지 시작 화면이 렌더링된다.
- `/journal`: 오늘 일기 시작 화면이 렌더링된다.

## 채팅/AI 흐름

- 모델을 하나 선택하고 질문 입력창이 활성 상태인지 확인한다.
- 토론 모드에서 추천 주제와 전문가 목록이 보이는지 확인한다.
- 공부 모드에서 스터디룸 진입 화면이 깨지지 않는지 확인한다.
- API 키가 없는 환경에서는 사용자에게 이해 가능한 오류가 표시되어야 하며 흰 화면이 나와서는 안 된다.

## 데이터/저장소

- localStorage/IndexedDB 기반 기능은 새로고침 뒤에도 기존 데이터가 유지되는지 확인한다.
- Supabase 환경 변수가 없는 로컬 환경에서도 앱 Shell은 렌더링되어야 한다.
- 삭제, 초기화, 내보내기 기능은 의도한 데이터만 대상으로 하는지 확인한다.

## 배포 확인

```bash
git status --short --branch
git log -1 --oneline
vercel ls expert-chat-forum
```

Production 배포가 새 커밋을 반영하지 않으면 Vercel 프로젝트의 Git 연결 또는 배포 훅 상태를 확인합니다.

## 릴리즈 메모

배포 전 변경 내용을 세 줄로 정리합니다.

- 사용자에게 보이는 변화
- 안정성/성능 변화
- 남아 있는 리스크 또는 후속 작업
