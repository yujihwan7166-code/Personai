# 마이위키 — 무한 문서 트리 (1단계)

작성 2026-07-17 · 대상 `/wiki` ([src/pages/Wiki.tsx](../../../src/pages/Wiki.tsx))

## 배경

현재 마이위키는 `분류 → 문서` 2단에서 멈춘다. 문서 안에 문서, 그 안에 또 문서를
매다는 게 불가능하다. 사용자가 원하는 건 깊이 제한이 없는 중첩이고, 유일한
망설임은 "그러면 사이드바에서 못 보는 것 아니냐"였다.

조직 수단도 5종(분류·태그·핀·`[[링크]]`·최근 본 문서)이 겹쳐 있다. 그중 분류는
문서당 1개만 붙는 데다, 무한 중첩을 도입하는 순간 "부모 문서"와 사실상 같은
개념이 된다.

## 범위

이 스펙은 **구조만** 다룬다. 본문은 손대지 않는다.

전체 로드맵 3단계 중 1단계다:

| 단계 | 내용 |
|---|---|
| **1 (이 문서)** | 분류 폐지 · `parent` 무한 트리 · 포커스 사이드바 · 빵가루 |
| 2 | Plate 에디터 이관 · `/` 메뉴 · `[[ ]]` 문법 제거 |
| 3 | 드래그 → 문서 연결 · AI 링크 추천 |

`[[ ]]` 제거는 확정된 결정이지만 2단계 소관이다. 본문이 플레인 텍스트인 한
링크를 글자로 적어두는 것 외에 방법이 없고, 그 제약은 블록 에디터로 옮겨야만
풀린다. 1단계 후에도 `[[ ]]`는 그대로 동작한다.

## 데이터 모델

```ts
interface WikiDoc {
  id: string;
  title: string;
  parent: string | null;   // ← cat: string 을 대체. null 이면 최상위
  tags: string[];
  pinned: boolean;
  updated: number;
  body: string;
}

interface Store {
  docs: WikiDoc[];
  recent: string[];
  // cats, collapsed 삭제
}
```

`WikiCat` 인터페이스와 `store.cats`가 사라진다. 개념이 5종 → 4종(문서·태그·핀·링크).
`store.collapsed`도 사라진다 — 사이드바가 3단만 그리므로 접을 대상이 없다.

필드 개수는 늘지 않는다. `cat` 한 칸이 `parent` 한 칸이 될 뿐이다.

### 색과 상징 글자

분류가 사라져도 시안의 색점·상징 글자(`영`·`음`)는 유지한다. **필드는 추가하지
않는다.**

- 문서의 색 = **뿌리 조상**의 `id`를 `CAT_PALETTE`(6색)에 해시한 값
- 상징 글자 = 뿌리 조상 제목의 첫 글자

사용자가 색을 고르는 UI도, 저장할 데이터도 없다. 화면은 현재와 동일하게 보인다.

### 마이그레이션 (`mywiki.v2` → `mywiki.v3`, 1회 자동)

기존 분류 4개를 **본문이 빈 최상위 문서 4개로 승격**한다.

- `WikiCat { id: 'c1', name: '영화·드라마' }` → `WikiDoc { id: 'c1', title: '영화·드라마', parent: null, body: '', tags: [], pinned: false }`
- 해당 분류에 속했던 문서는 `parent: 'c1'`

분류 id를 그대로 문서 id로 재사용하므로 자식의 `parent` 매핑이 자명하다.
태그·핀·본문·`[[링크]]`·백링크·`recent`는 건드리지 않는다.

`seed()`도 같은 모양으로 다시 쓴다 — 분류 4개가 최상위 문서, 문서 10개가 그 자식.

`v2` 키를 읽어 변환 후 `v3`로 저장한다. `v3`가 있으면 그대로 읽는다. 손상된
저장분은 기존과 같이 시드로 대체한다.

### 불변 규칙

- **순환 금지** — 문서의 `parent`를 자기 자신 또는 자기 자손으로 설정할 수 없다.
  위반 시 트리 순회가 무한 루프에 빠진다. 상위 문서 선택 UI에서 자손을 목록에서
  제외하는 방식으로 막는다.
- **삭제 시 자식 승격** — 자식이 있는 문서를 삭제하면 자식들의 `parent`가 삭제된
  문서의 `parent`로 바뀐다(한 단계 위로 올라온다). 자손을 함께 삭제하지 않는다.
  부모 하나를 지웠다가 손자까지 조용히 사라지는 것이 가장 위험한 사고다.
- **고아 방지** — `parent`가 존재하지 않는 id를 가리키면 최상위로 간주해 렌더한다.

## 사이드바 — 포커스 트리

깊이와 무관하게 **항상 최대 3단**만 그린다.

```
← 영화·드라마            부모 (클릭 → 부모로 이동)
  2026년 영화 기록  3     형제
▸ 봉준호 필모 정리  2     현재 문서 (채움 알약)
    ├ 기생충 각본 분석    자식 (한 단 들여쓰기)
    └ 마더 재감상 메모
  볼 영화 리스트          형제
```

자식을 클릭하면 트리가 **통째로 한 칸 민다**. 방금 보던 문서가 부모 자리로,
그 자식들이 형제 자리로, 손자가 자식 자리로 온다. 30단을 파고들어도 사이드바
모양은 위 그림과 같다. 들여쓰기가 오른쪽으로 밀려 글자가 잘리는 일이 없다.

**홈 상태**에서는 최상위 문서만 나열한다 — 현재의 분류 목록과 시각적으로 동일하다.
색점·상징 글자·우측 숫자가 그대로다. 다만 우측 숫자의 의미가 "이 분류의 문서 수"에서
**"이 문서의 자식 수"**로 바뀐다.

사이드바 상단(로고·검색·`/` 단축키)과 `고정됨`·`최근 본 문서` 섹션은 현행 유지한다.
`/` 검색 포커스 단축키는 `textarea` 밖에서만 동작하므로 2단계의 `/` 메뉴와 충돌하지
않는다.

푸터의 `문서 N · 분류 M`은 `문서 N`으로 바뀐다.

### 새 문서를 만드는 위치

무한 트리에서 가장 헷갈리는 지점이므로 **버튼 라벨이 위치를 말한다.**

- 홈: `+ 새 문서` → `parent: null`
- 문서 보는 중: `+ 여기 아래 새 문서` → `parent: 현재 문서 id`
- 트리 각 행의 작은 `+`: 그 행의 문서 아래
- 검색 결과 없음 화면의 "새 문서 만들기": `parent: null`
- `[[없는 문서]]` 링크 클릭: `parent: 현재 보던 문서 id`

## 빵가루

본문 상단, 현재 `[영] 영화·드라마`가 있는 자리를 대체한다.

```
영화·드라마 › 봉준호 필모 정리 › 기생충 각본 분석
```

각 조각은 클릭 시 그 문서로 이동한다. 4단을 넘으면 중간이 `…`로 접히고, 클릭하면
펼쳐진다.

사이드바가 3단만 보여주므로 **"내가 지금 어느 깊이에 있는가"는 전적으로 빵가루가
책임진다.** 포커스 트리와 빵가루는 한 쌍이며 따로 뗄 수 없다.

## 문서 이동

편집 화면의 분류 `select`가 **상위 문서 `select`**가 된다.

- 트리 순서대로 들여쓰기해 표시
- 첫 항목: `— 최상위로 —` (`parent: null`)
- 자기 자신과 자기 자손은 목록에서 제외 (순환 금지)

문서 수백 개 규모에서는 `select`가 무너지지만, 그때 검색 피커로 교체하면 된다.
지금 만들면 과잉이다.

## 영향받는 나머지 화면

- **검색 결과 카드 / 태그 보기 카드** — 분류 이름·색점 자리에 **뿌리 조상**의
  이름·색점이 들어간다.
- **문서 보기 상단** — `CatSym` + 분류명 → 빵가루.
- **홈 대시보드** — 고정된 문서·최근 본 문서·태그 섹션은 변경 없음.
- **`[[링크]]` · 백링크** — 제목 기준이므로 트리와 무관하게 현행 동작 유지.
- **검색 로직** — 제목·본문·태그 기준이므로 변경 없음.

## 구현 단위

`Wiki.tsx`가 이미 701줄이고 이번 변경으로 트리 순회 로직이 더해진다. 순수 함수를
분리해 파일이 비대해지는 것을 막는다.

**`src/lib/wiki/tree.ts`** (신규, 순수 함수 · 테스트 대상)

| 함수 | 역할 |
|---|---|
| `childrenOf(docs, parentId)` | 직계 자식 |
| `ancestorsOf(docs, id)` | 뿌리 → 부모 경로 (빵가루용) |
| `rootOf(docs, id)` | 뿌리 조상 (색·상징 글자용) |
| `descendantIdsOf(docs, id)` | 모든 자손 id (순환 방지·삭제용) |
| `isDescendant(docs, id, maybeAncestorId)` | 순환 검사 |
| `moveOptions(docs, id)` | 상위 문서 select 목록 (자손 제외, 들여쓰기 깊이 포함) |
| `deleteWithPromotion(docs, id)` | 삭제 + 자식 승격 |
| `focusView(docs, activeId)` | `{ parent, siblings, children }` — 포커스 트리 |
| `colorOf(docs, id)` / `symOf(docs, id)` | 뿌리 기반 색·상징 글자 |

모든 함수는 고아·순환·빈 트리에서도 죽지 않아야 한다(방어적 순회, 방문 집합).

**`src/lib/wiki/migrate.ts`** (신규, 순수 함수 · 테스트 대상)

`migrateV2ToV3(raw)` — `cats` + `docs.cat` → `docs.parent`.

**`src/pages/Wiki.tsx`** — 위 함수들을 소비. 사이드바 트리·빵가루·상위 문서 select
교체.

## 테스트

`src/test/wikiTree.test.ts`, `src/test/wikiMigrate.test.ts` (Vitest, 기존 관례).

- `childrenOf` / `rootOf` / `ancestorsOf` 기본
- 깊이 5단 이상에서 `focusView`가 항상 3단만 반환
- `isDescendant` — 자기 자신, 직계, 손자, 무관한 문서
- `moveOptions` — 자손이 제외되는가
- `deleteWithPromotion` — 자식이 조부모로 승격, 최상위 문서 삭제 시 자식이 `null`로
- 고아 `parent` → 최상위로 간주
- 순환 데이터가 주입돼도 순회가 종료 (방문 집합)
- `migrateV2ToV3` — 분류 4개 → 최상위 문서 4개, 자식 매핑, 태그·핀·본문 보존
- `migrateV2ToV3` — `cats`가 빈 배열, `cat`이 없는 문서 등 결손 입력

## 하지 않는 것

- 본문 에디터 변경 (2단계)
- `[[ ]]` 문법 제거 (2단계)
- `/` 슬래시 메뉴 (2단계)
- 드래그 → 문서 연결, AI 링크 추천 (3단계)
- 드래그 앤 드롭 문서 이동 — `select`로 충분하다
- 문서별 색 지정 UI — 뿌리 기반 자동
- 그래프 뷰
